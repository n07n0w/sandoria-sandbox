# Docker Deployment Guide

This guide explains the modernized Docker-based deployment system for the Sandoria Sandbox application.

## Architecture Overview

- **Build & Push**: GitHub Actions builds Docker images and pushes to GitHub Container Registry (ghcr.io)
- **Host Database**: MySQL runs directly on the host server (not in container)
- **Container App**: Application runs in Docker container, connects to host database
- **Deployment**: SSH deployment via docker-compose commands

## Required Server Setup

### 1. Database Setup (Host)

Ensure MySQL is running on the host:

```bash
# Install MySQL (Ubuntu/Debian)
sudo apt update
sudo apt install mysql-server

# Create database and user
sudo mysql -u root -p
```

```sql
CREATE DATABASE sandbox;
CREATE USER 'sandboxuser'@'localhost' IDENTIFIED BY 'sandboxuser_pass';
CREATE USER 'sandboxuser'@'172.%' IDENTIFIED BY 'sandboxuser_pass'; -- For Docker containers
GRANT ALL PRIVILEGES ON sandbox.* TO 'sandboxuser'@'localhost';
GRANT ALL PRIVILEGES ON sandbox.* TO 'sandboxuser'@'172.%';
FLUSH PRIVILEGES;
EXIT;
```

Import your database:
```bash
mysql -u sandboxuser -p sandbox < DB/timeweb.sandbox.sql
```

### 2. Server Dependencies

```bash
# Install Docker & Docker Compose
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo apt install docker-compose

# Add user to docker group
sudo usermod -aG docker $USER

# Create project directory
mkdir -p /home/sandoria-sandbox
cd /home/sandoria-sandbox

# Clone repository
git clone https://github.com/your-username/sandoria-sandbox.git .
```

### 3. GitHub Secrets Configuration

Add these secrets to your GitHub repository:

- `HOST`: Your server IP address
- `USER`: SSH username (e.g., `ubuntu`)
- `KEY`: SSH private key for authentication
- `SENTRY_DSN`: Your Sentry DSN (optional)
- `SENTRY_ENVIRONMENT`: Environment name (e.g., `production`)
- `SENTRY_SAMPLE_RATE`: Error sampling rate (e.g., `0.1`)

## Deployment Process

### Automatic Deployment

The deployment triggers on:
- Push to any branch (builds image)
- Only `main`/`master` branch deploys to production

### Manual Deployment

1. **Build & Push Image**:
   ```bash
   # GitHub Actions handles this automatically
   # Or manually:
   docker build -t ghcr.io/your-username/sandoria-sandbox:latest .
   docker push ghcr.io/your-username/sandoria-sandbox:latest
   ```

2. **Deploy on Server**:
   ```bash
   cd /home/sandoria-sandbox

   # Set environment variable
   export DOCKER_IMAGE=ghcr.io/your-username/sandoria-sandbox:latest

   # Stop & remove old container
   docker-compose -f docker-compose.prod.yml stop app
   docker-compose -f docker-compose.prod.yml rm -f app

   # Pull new image & start
   docker pull $DOCKER_IMAGE
   docker-compose -f docker-compose.prod.yml up -d app
   ```

## Configuration Files

### docker-compose.prod.yml
- Uses host database connection via `host.docker.internal`
- Exposes app on port 3001 (maps to container port 3000)
- Includes health checks and auto-restart

### .env (Generated by deployment)
```
# Sentry Configuration
SENTRY_DSN=your-sentry-dsn
SENTRY_ENVIRONMENT=production
SENTRY_SAMPLE_RATE=0.1

# Docker Image
DOCKER_IMAGE=ghcr.io/your-username/sandoria-sandbox:latest

# Database Configuration (host database connection)
DB_HOST=localhost
DB_PORT=3306
DB_USER=sandboxuser
DB_PASSWORD=sandboxuser_pass
DB_NAME=sandbox

# Application Configuration
NODE_ENV=production
PORT=3000
```

## Health Monitoring

### Health Check Endpoint
- URL: `http://your-server:3001/health`
- Returns JSON with database status and version info

### Application Monitoring
```bash
# Check container status
docker-compose -f docker-compose.prod.yml ps

# View logs
docker-compose -f docker-compose.prod.yml logs app

# Follow logs
docker-compose -f docker-compose.prod.yml logs -f app
```

## Troubleshooting

### Database Connection Issues
1. Check MySQL is running: `sudo systemctl status mysql`
2. Test connection: `mysql -u sandboxuser -p sandbox`
3. Check container network: `docker network ls`
4. Verify user permissions for Docker subnet

### Container Issues
1. Check image exists: `docker images | grep sandoria-sandbox`
2. Check container logs: `docker-compose -f docker-compose.prod.yml logs app`
3. Test health endpoint: `curl http://localhost:3001/health`

### Deployment Failures
1. Verify GitHub secrets are set correctly
2. Check server SSH access
3. Ensure server has enough disk space
4. Verify Docker daemon is running

## Security Notes

- Database credentials are in plain text in .env file
- Consider using Docker secrets for production
- Regularly update base Docker images
- Monitor container resource usage
- Set up proper firewall rules (only expose port 3001)
